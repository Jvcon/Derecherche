A search picker should not fight the page

Demo article · select any sentence to test the SelectionBar

Search is rarely a single action. A user may start with a phrase, move to a code repository, then jump to a paper or a dictionary. The useful part is not the list of engines; it is the routing layer that keeps the query intact while the destination changes.

Derecherche treats the catalog as data and the picker as a host-specific shell. The same engine records can power a userscript, a browser extension, a terminal picker, or a desktop launcher. Category navigation is the primary axis; provider branding is only a visual grouping.

Stable ordering for muscle memory. Recommendation as a separate strip, never as a silent reorder.

The Palette uses a two-level category tree. Selecting a category enters it; selecting an engine opens the target in a new tab. Typing filters globally, so a user who knows the engine name does not have to navigate the tree. Number shortcuts stay bound to the stable list, not to the dynamic recommendations.

Selection is a second context. When text is selected, a small floating action can search that exact phrase without touching the page search box. The action stays out of inputs and editable regions, does not steal focus, and hides when the selection disappears.

The article page exists to test those interactions against real prose. Select a sentence, try the floating action, then open the Palette and filter for an engine such as GitHub, Wikipedia, or Wolfram Alpha.
